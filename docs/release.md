# Выпуск и откат

Собрать проверенный commit командой `npm ci && npm test && npm run build`. В GitHub остаются исходники и документы проекта. На VPS переносится только содержимое dist и манифест.

1. Прочитать текущий `index.html` каталога, проверить webroot и отсутствие неожиданного состояния целевого пути.
2. Сохранить резервную копию каталога и предыдущий релиз страницы, записать SHA-256 исходного каталога.
3. Загрузить артефакт во временную папку на том же файловом разделе. Проверить все файлы по manifest.json.
4. Проверить `nginx -t`. Переключить версию атомарной операцией. Для первой публикации достаточно атомарного переименования подготовленного каталога.
5. Патч карточки строится от свежего каталога. Перед записью повторно сравнить SHA исходного каталога, чтобы не затереть параллельные изменения. Сохранить порядок и количество существующих карточек; увеличить счётчик на одну.
6. Проверить HTTPS-страницу, ресурсы по манифесту, темы, режим показа и карточку каталога.
7. Сохранить release ID, commit и результаты в локальном release-report.json. Пути к секретам и содержимое конфигурации доступа не входят в репозиторий.

Откат первого релиза: восстановить сохранённый каталог, а новый маршрут переместить в rollback-каталог. Перед восстановлением сравнить текущий каталог с SHA только что установленного файла: при чужих изменениях остановиться и удалить только карточку этого проекта вручную. Для последующих релизов возвращать предыдущую версию страницы и соответствующее изменение каталога.

Релиз не должен менять соседние приложения или nginx-конфигурацию, если существующая статическая раздача уже обслуживает путь. HTML обновляется при обращении; сборщик хеширует CSS/JS. При замене фотографий или шрифтов в будущем изменить имя ресурса либо пересмотреть кеширование для этих файлов.

## Обновление V2

Для V2 каталог проектов не меняется: карточка уже существует. Перед выпуском проверяются текущий манифест страницы и SHA каталога. Предыдущая версия целиком сохраняется в резервной копии вне webroot. Новая версия проверяется во временном каталоге на том же разделе и обменивается с действующим каталогом через Linux `renameat2(RENAME_EXCHANGE)`. Откат использует сохранённую копию и такую же атомарную замену с проверкой текущего манифеста. Алгоритм обмена проверяется в изолированных временных каталогах; реальный откат production не имитируется успешным тестом.

Контроль V2: 12 сцен × 4 разрешения 16:9 × 2 темы; мобильные ширины 320/390/768; полный цикл графика, остановка за экраном, выбор подсказок, календарь, темы, no-JS и reduced motion. Отчёт — `docs/qa-v2.json`.
